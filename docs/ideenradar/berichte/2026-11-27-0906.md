## RADAR-003: Datenlücken in Energiekurven — Jetzt testen

Die aktuelle [Recharts-Line-Dokumentation](https://recharts.github.io/en-US/api/Line/) beschreibt connectNulls mit Standard false. Das hilft nur, wenn fehlende Werte als solche beim Diagramm ankommen. In [EnergyTimeChart.jsx](https://github.com/felixdoering05-prog/GST_Teamprojekt_Team_1/blob/c991073f846cb018153f2a82d245c595ecc5044e/dashboard/base44-frontend/src/components/energy/EnergyTimeChart.jsx) werden gelieferte Werte durch Number(point.value) umgewandelt. Ein explizites null würde dadurch 0; ein vollständig fehlender Zeitpunkt wird hingegen als Zeile ohne Serienwert ergänzt. Das ist ein statischer Befund, kein Nachweis, dass die API tatsächlich null liefert oder Produktivdaten betroffen sind.

[Home Assistant Sensor states](https://www.home-assistant.io/integrations/sensor/#sensor-states) trennt Messwerte von unbekannten/nicht verfügbaren Zuständen. Die Seite zeigt 2026.11.3; Veröffentlichungsdatum und Dokumentationslizenz separat ungeklärt.

**Kleiner Test:** Dieselbe synthetische Reihe mit echtem 0, explizitem null und ausgelassenem Zeitpunkt an die isolierte Web-Ansicht geben. Erwartung: 0 bleibt Messwert, beide Ausfälle bleiben als fehlende Daten erkennbar und werden nicht als bestätigter Nullverbrauch erklärt. Tooltip und Diagramm prüfen. 20–30 Minuten geschätzt, nicht ausgeführt. Ergänzung von RADAR-003 statt neuer Eintrag.

**Passung, Kosten, Sicherheit:** Bereits eingesetztes React-Diagramm; Express/PostgreSQL und reale Sensoren für den UI-Versuch nicht erforderlich. Keine neue Abhängigkeit oder Dienstgebühr. Nur synthetische Werte, keine Übertragung von Gebäude-/Nutzerdaten.
