## RADAR-007 · Bleibt die Tür bei gedrehter PDF-Seite im richtigen Raum?

**Jetzt testen.** D21 liest Vektorpläne mit pdfplumber und rechnet Pfadkoordinaten anhand der Seitenhöhe um. PR #191 korrigiert die Erkennung des Planrahmens. Eine andere Frage ist, ob eine reine PDF-Seitendrehung die Zuordnung von Türen und Raumnamen verändert. Ein Fehler ist bislang nicht nachgewiesen. [PDF-Leser auf main](https://github.com/felixdoering05-prog/GST_Teamprojekt_Team_1/blob/9bdbd19/dashboard/backend/plan-extract/planextract/read_pdf.py) · [Rahmenkorrektur](https://github.com/felixdoering05-prog/GST_Teamprojekt_Team_1/pull/191)

**Testvorschlag für Grundrisserkennung und IFC-Vorschau, geschätzt eine Stunde.** Einen synthetischen asymmetrischen Zweiraumplan mit bekannter Wandlänge und einer Außentür in Raum A zweimal bereitstellen. Bei der zweiten Datei ausschließlich den PDF-Seiteneintrag Rotate auf 90 Grad setzen. Beide lokal in derselben Testumgebung verarbeiten. Bestanden, wenn Wandlängen innerhalb der bestehenden Rundungsgenauigkeit übereinstimmen, beide Namen ihrem Raum zugeordnet bleiben und die Außentür in beiden Vorschauen auf derselben Gebäudeseite von Raum A sitzt. Eine gemeinsame Drehung der gesamten Darstellung ist zulässig. Keine privaten Pläne, neuen Dienste oder Pakete erforderlich.

**Quelle und Übertragbarkeit.** PyMuPDF dokumentiert ausdrücklich, welche Koordinaten gedreht oder ungedreht zurückkommen. Das liefert die Idee für das Dateipaar. Für das Verhalten des D21-Lesers ist der Versuch entscheidend, weil dieser eine andere Bibliothek verwendet. GitHub führt PyMuPDF unter AGPL-3.0 und meldet Release 2.1 vom 2. November 2026. Für den Versuch genügt die bestehende D21-Verarbeitung mit pdfplumber (MIT).
